5. AI FINDER
==================================================

Provide a large text area where a student describes what kind of alumni they are looking for.

Example:

"I am interested in cybersecurity and want to find an alumnus who works in cybersecurity and can guide me about internships."

The system should:

1. Send the student's natural-language query to the Groq LLM.
2. Extract useful structured requirements into JSON.

Example:

{
    "interests": ["cybersecurity"],
    "skills": [],
    "job_roles": ["cybersecurity"],
    "location": [],
    "graduation_year": null,
    "branch": null,
    "experience": null,
    "other_requirements": []
}

3. Use structured requirements for exact/hard filtering where appropriate.
4. Generate an embedding for the student's query or the semantic portion of the query.
5. Search Qdrant for semantically similar alumni.
6. Retrieve the top 5-10 matching alumni IDs.
7. Fetch the complete alumni records from PostgreSQL.
8. Return results in descending order of relevance.
9. Display a meaningful match score.
10. Display a short explanation for why an alumnus matched.

The final UI should show:

- Alumni name
- Current company
- Current role
- Skills
- Graduation year
- Location
- Match score
- Why they matched

Clicking an alumnus should open the detailed alumni profile.

IMPORTANT:
Do not blindly use Qdrant for all filtering.
Use PostgreSQL for exact structured filters and Qdrant for semantic similarity.

==================================================
6. QDRANT
==================================================

PostgreSQL remains the source of truth.

For every alumni:

1. Collect relevant profile information.
2. Collect relevant survey answers.
3. Collect relevant career journey information.
4. Collect relevant advice/free-text information where useful.
5. Construct a consolidated text representation of the alumnus.
6. Generate an embedding.
7. Store one Qdrant point for that alumnus.

Example payload:

{
    "alumni_id": 123
}

The Qdrant vector is the embedding.

Use a single clearly defined collection for alumni semantic search unless there is a strong implementation reason otherwise.

Document:
- Collection name
- Embedding model
- Vector dimension
- Distance metric

==================================================
7. QDRANT SYNCHRONIZATION
==================================================

This requirement is mandatory.

Whenever an alumnus changes information that contributes to the semantic representation:

- Profile
- Skills
- Interests
- Career journey
- Survey answers
- Relevant advice

the system must:

1. Update PostgreSQL.
2. Reconstruct the alumnus semantic document.
3. Generate a new embedding.
4. Update/upsert that alumnus's Qdrant point.

This prevents stale vectors.
